### C1
写一个 `stats_node`：订阅 `/my_sensor/v`，**每 5 秒**打印"最近这一个周期内"的：帧数、均值、标准差。

硬约束：**不许把数据存进 list。**

提示：方差可以用增量方式维护——你只需要 `count`、`sum_v`、`sum_v2` 三个量：

```
σ² = Σv²/n − (Σv/n)²
```

附加要求：每次打印完，统计量要**清零**（这是"窗口统计"，不是"累计统计"）。

```python

from std_msgs.msg import Float32
# count 帧数 | sum_v 均值	| sum_v2 标准差
class StatsNode(Node):
    def __init__(self):
        super().__init__('stats_node')
		self.subscription = self.create_subscription(Float32,'/my_sensor/v',self.on_value,10)
        self.timer = self.create_timer(5.0,self.on_report)
        self.count = 0.0		
        self.sum_v = 0.0
        self.sum_v2 = 0.0

            f'stats_node 已启动 | 监听 /my_sensor/v | 每 {period}s 汇报一次'
        )
    def on_value(self,msg):
        self.count += 1
        self.sum_v += msg.data
        self.sum_v2 += msg.data ** 2
```

# 答案与解析（做完再翻）

## A 组答案

**A1**
能。一个节点可以挂任意多个发布者、订阅者、定时器、服务、动作。
拆节点的判据：**问自己"这两件事要不要一起活、一起死？"** 要 → 同一个节点；不要（需要独立启停、崩溃隔离、真并发）→ 拆。

**A2**

- (a) `/fake_sensor`。launch 的 `name=` 是**进程级重映射**（等价 `--ros-args -r __node:=fake_sensor`），对该进程内**所有**节点生效。
- (b) `/my_sensor`。代码里 `FakeSensorNode('my_sensor')` 的参数就是节点名，此时没有 launch 来覆盖它。
- (c) 两个实例会被**双双改成 `/fake_sensor`** → 图里出现同名节点。表现：`ros2 node list` 打印 `WARNING: ... nodes in the graph that share an exact name`，日志出现 `[rcl.logging_rosout]: Publisher already registered for provided node name`，话题的 `Publisher count` 变成 2。命令：**`ros2 node list`**。

**A3**
- (a) 100 行。
- (b) 1 行。
- (c) 日志本身是有开销的（格式化、写终端、发布到 `/rosout`）。默认 `SingleThreadedExecutor` 下这些活儿都在**同一个线程**里干，会直接挤占回调的执行时间，严重时导致定时器丢帧。所以生产代码里高频路径的日志应该降到 `debug`。

**A4**
选 **(b)**。(a) 是 O(n) 内存：100 万帧 × 8 字节 ≈ 8 MB，跑一整天就顶飞了；(b) 只占 3 个变量，O(1)，跑一年也一样。这就是"边收边算"。

**A5**
- (a) **不需要**。`--symlink-install` 下 Python 源文件是软链，改完直接生效。
- (b) **需要**重新 build。`entry_points` 属于安装元数据，会写进 `egg-info`；旧的可执行名还会残留（`install/<包>/lib/<包>/` 里能看到两个），要清理得删掉该包的 `build/`+`install/` 再 build。

**A6**
返回 `0.0`。`gauss(mean, sigma)` 的第二个参数是**标准差**：σ=0 时正态分布退化成一个尖峰，所有样本都等于均值 0 —— 不是"随机失败"，是数学必然。所以要让 noise 生效，必须给非零值（`noise:=0.3`）。

**A7**
- (a) rqt_plot 画的是**话题里的某个字段**，不是话题本身。只给话题名，它不知道画哪个字段。
- (b) `/my_sensor/v/data`（`std_msgs/Float32` 的字段名固定叫 `data`）。
- (c) `/话题名/linear/x` —— 嵌套字段用 `/` 逐层往下写。

**A8**
其他 4 个定时器**全部被拖慢**。默认 `SingleThreadedExecutor` 下，一个节点里所有定时器回调和订阅回调**共用一个线程排队执行**；A 跑 0.5 秒期间，其他回调都在队列里等着，会延迟甚至丢帧。
两条路：
1. **把 A 拆成独立节点**（进程隔离，工程里最常用）
2. 换 `MultiThreadedExecutor` + `callback_group`，把 A 放进独立的 `MutuallyExclusiveCallbackGroup`，让它在另一个线程跑

**B2（6 处）**

| # | 问题 | 后果 |
|---|---|---|
| 1 | `self.create_timer(timer_period,)` —— `timer_period` **从未定义**，而且 `create_timer` 必须传回调 | `NameError`；就算补上周期，还缺回调参数 → `TypeError` |

**B3（4 处）**

| # | 问题 | 后果 |
|---|---|---|
| 1 | `declare_parameter('amplitude', 'Float32')` —— 默认值写成了字符串 | 参数类型变成 string，后面 `amplitude * math.sin(...)` 会抛 `TypeError: can't multiply sequence by non-int of type 'float'`。默认值应该是 `1.0` |

| 3 | `def rate_callback(self, msg)` —— 定时器回调**不接收消息** | `create_timer` 调用它时不传参数 → `TypeError: missing 1 required positional argument: 'msg'`。应写成 `def rate_callback(self):` |

另外还漏了：`msg.data` 被赋成字符串，而 `Float32.data` 是 float 类型 —— 应该 `msg.data = float(value)`。

## C 组参考答案

**C1**

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""stats_node —— 窗口统计：每 N 秒汇报本窗口的帧数 / 均值 / 标准差"""

import math

import rclpy
from rclpy.executors import ExternalShutdownException
from rclpy.node import Node
from std_msgs.msg import Float32


class StatsNode(Node):

    def __init__(self, name):
        super().__init__(name)

        self.declare_parameter('window', 5.0)
        self.declare_parameter('topic_name', '/my_sensor/v')

        self._reset()                       # 三个统计量

        topic = self.get_parameter('topic_name').value
        self.sub = self.create_subscription(Float32, topic, self.on_value, 10)

        window = self.get_parameter('window').value
        self.timer = self.create_timer(window, self.on_report)

        self.get_logger().info(f'stats_node 启动 | {topic} | 窗口 {window}s')

    def _reset(self):
        """窗口统计：每个周期开始（或结束时）清零"""
        self.count = 0
        self.sum_v = 0.0
        self.sum_v2 = 0.0

    def on_value(self, msg):
        v = msg.data
        self.count += 1
        self.sum_v += v
        self.sum_v2 += v * v                # 增量维护 Σv²

    def on_report(self):
        if self.count == 0:
            self.get_logger().warn('本窗口没有收到数据')
            return

        n = self.count
        mean = self.sum_v / n
        # σ² = E[v²] − (E[v])²；浮点误差可能让结果略小于 0，用 max 兜底
        var = max(0.0, self.sum_v2 / n - mean * mean)

        self.get_logger().info(
            f'窗口统计 | 帧数={n} | 均值={mean:+.3f} | 标准差={math.sqrt(var):.3f}'
        )

        self._reset()                       # 打印完清零


def main(args=None):
    rclpy.init(args=args)
    node = StatsNode('stats_node')
    try:
        rclpy.spin(node)
    except (KeyboardInterrupt, ExternalShutdownException):
        pass
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```

要点：
- **窗口统计 vs 累计统计**：累计统计"从开机到现在的均值"，会越来越钝；窗口统计反映"最近一段的状态"，才是监控真正要的。
- `max(0.0, ...)` 那一下不是多余的：`E[v²] − (E[v])²` 在数值上可能算出 `-1e-17`，`math.sqrt` 会直接抛 `ValueError: math domain error`。
- 公式本身你在《信号与系统》里见过——这里是它第一次变成代码。

```python
import math

# on_timer 里
wave = self.get_parameter('wave').value

if wave == 'square':
    signal = math.copysign(1.0, math.sin(phase))     # 方波
elif wave == 'saw':
    signal = 2.0 * ((freq * self.t) % 1.0) - 1.0     # 锯齿波

```

要点：
- 字符串参数的默认值写 `'sin'`，**不能**写 `'Float32'` 那种"把类型名当默认值"的东西（这是你草稿里的头号错误）。
- 用 `else` 兜底而不是 `if wave == 'sin'`：参数传错了也不会崩，行为退化成默认波形。

# 附：2026-09-19 实跑复核 —— 窗口统计输出正确性验证

> 复核对象：`ros2 run sensor_bridge stats_node` 的实测输出（截图）
> 复核方式：把观测值代回理论公式，看四条独立证据是否**同时**成立

实测现象：每 5.000 秒一行；`均值` 在 **+0.058 / −0.058** 之间交替；`方差` 恒为 0.497；`标准差` 恒为 0.705。
（⚠️ 订正：`标准差` **不是**恒定值，它跟着 |均值| 走，范围 0.6956~0.7071。原因见 **附1.5**。）

**结论：完全正确。** 而且这四条证据互相独立，不可能同时由巧合造成。

## 证据 1 · 周期准确

相邻两行的时间戳差 = 4.999 ~ 5.000 s → 窗口定时器精准。
（时间戳 `1789825021.798752258` 是 ROS 时钟的「秒.纳秒」，不是浮点秒——两者别混。）

## 证据 2 · 方差落在理论值上

正弦波的方差有闭式解：

```
Var = A² / 2        A = amplitude = 1.0  →  Var = 0.5
Std = A / √2 = 0.7071
```

实测 0.497 / 0.705，与理论值差 0.6%——这 0.6% 来自下面证据 4 里那个残余均值。

## 证据 3 · 一行恒等式自检（★ 记住这招）

```python
var + mean ** 2 == A ** 2 / 2        # 只有纯正弦、无噪声时成立
```

代入实测值：`0.497 + 0.058² = 0.497 + 0.003364 = 0.50036 ≈ 0.5` ✅

**这行自检的价值**：以后任何窗口统计只要算错了（清零漏了、累加器混了、类型错了），
这个恒等式会第一时间露馅。写统计代码时先在心里留一个「理论值」当锚点——
**没有理论值的输出只能看出"在动"，看不出"对不对"。**

## 证据 4 · 均值符号交替是数学必然，不是抖动

| 量 | 值 |
|---|---|
| 采样率 | 10 Hz |
| 窗口长度 | 5 s → **50 个样本** |
| 信号频率 | 0.5 Hz → 每周期 20 个样本 |
| 一个窗口覆盖 | 50 / 20 = **2.5 个周期**（非整数！） |

非整数周期 → 窗口内必然剩下一块**没被抵消的残差**。
而相邻窗口的相位推进恰好是 2.5 周期 ≡ **半个周期**（mod 1），
于是残差的符号**每次都翻转** → 均值在 ± 两个相同数值之间交替。

残差的理论上界（50 样本的等比级数求和）：

```
|mean| ≤ A · 2 / (n · 2·sin(0.05π))
       = 1.0 · 2 / (50 · 0.312869)
       = 0.1278
```

实测 |0.058| 落在区间内 ✅。复算脚本（`freq=0.5, rate=10, win=5`）跑出来的是
`mean = ±0.0685，var = 0.4953，std = 0.7038`——与实测同构，只是初相不同。

**这张图还顺带证明了「窗口清零」真生效了**：如果累加器没清零，第 k 个窗口算的是
「开机至今的累计统计」，其均值幅度会按 **1/k** 衰减——到第 11 行早该是 0.005 而不是 0.058，
方差也会一路漂移。实测幅度 11 行纹丝不动 → 每窗口都重新计数 ✅
（`self.count = 0` 那三个等号，确实是用对的那个等号。）

## 立刻可以做的验证实验

把频率改成能整除窗口的值，均值必须塌到 0：

```bash

ros2 run sensor_bridge my_sensor_wave --ros-args -p freq:=0.4
ros2 run sensor_bridge stats_node
```

期望：`均值=+0.000`（小数点后三位全是 0）。
**如果它没塌到 0，说明清零那道题还没真做对。** 这个实验比任何"看曲线在动"都严格。

## 附1.5 · 订正（2026-09-22）：`标准差` 不是恒定的 0.705

同一份代码、同样的参数，2026-09-22 再跑一次，输出变成了：

```
均值=+0.126|帧数=50 |标准差 = 0.696
均值=-0.126|帧数=50 |标准差 = 0.696
...
```

**两个数都对。** 它们是同一条公式在两个不同启动相位下的取值。

### 为什么

滑动窗口 `W = 5 s`，信号周期 `T = 2 s` → `W / T = 2.5`，**含 2.5 个周期**。

- 那 2 个整周期严格抵消，贡献为 0；
- 多出来的**半个周期没有配对**，留下残差。残差幅度与窗口起始相位有关：

```
|mean| ≤ 2 / (π·W) = 2 / (5π) = 0.1273        （取到等号的相位）
```

- 而 `σ² = E[v²] − mean²`，其中 `E[v²]` 是**精确的 0.5**（与相位无关），所以：

```
σ = sqrt(0.5 − mean²)
    → |mean| = 0.058 → σ = 0.705   （09-19 那次的相位）
    → |mean| = 0.126 → σ = 0.696   （09-22 这次的相位）
```

所以**σ 的可达区间是 [ sqrt(0.5 − 0.1273²), 0.7071 ] = [0.6956, 0.7071]**，
不是单点 0.705。09-19 那次只是碰巧落在上沿。

### 一行自检（比看"数字在动"严格得多）

```
σ² + mean² == A²/2          →  0.6958² + 0.12605² = 0.5000  ✅
```

两次实测都精确满足它 —— 这一条比"标准差看起来像 0.7"有力得多。

### 想看到教科书上的 0.707，让窗口含整数个周期

```bash
# 4 s ÷ 2 s = 2 个整周期
ros2 run sensor_bridge stats_node --ros-args -p report_period:=4.0
```

期望输出：`均值=+0.000|帧数=40 |标准差 = 0.707`。

或者保持 5 s 窗口、把信号频率改成能整除窗口的值：

```bash
ros2 run sensor_bridge my_sensor_wave --ros-args -p freq:=0.4   # 5s = 2 个整周期
```

两条命令都是**判据**：只要均值没塌到 0.000，就是清零那道题还没真做对。

## 附2 · 一个被夸大了的坑：`E[v²] − E[v]²` 到底什么时候会坏

> **更正说明（2026-09-19）**：本节初稿写成「double 白丢一半有效位、接上 STM32 必撞」——
> **这个说法夸大了**。下面是实测数据，结论以数据为准。

### 实测（N=50 帧 × 200 次重复，用 struct 模拟 float32）

| 情形（偏置 ± 波动） | 真实方差 | float64 朴素 | float64 Welford | float32 朴素 | float32 Welford |
|---|---|---|---|---|---|
| 0 ± 1.0 | 1.0 | 1.6e-1 | 1.6e-1 | 1.8e-1 | 1.8e-1 |
| 2048 ± 5（真 ADC 长相） | 25 | 1.6e-1 | 1.6e-1 | 1.6e-1 | 1.6e-1 |
| 25000 ± 15（温度×100） | 225 | 1.5e-1 | 1.5e-1 | **inf（11/200 算出负数）** | 1.6e-1 |
| 2048 ± 0.05 | 0.0025 | 1.5e-1 | 1.5e-1 | **inf（70/200 负数）** | 1.7e-1 |
| 1e6 ± 1 | 1.0 | 1.7e-1 | 1.6e-1 | **inf（88/200 负数）** | 1.7e-1 |
| 1e7 ± 1 | 1.0 | 1.7e-1 | 1.6e-1 | 溢出 | — |

（`1.6e-1` ≈ 16% 是 **n=50 时方差估计本身的统计涨落**，不是数值误差：
理论相对标准差 `√(2/(n−1)) = √(2/49) ≈ 20%`。两列一样大 = 两种算法都对。）

### 修正后的结论（三句话）

1. **Python 的 float64 下，这个公式是安全的。** 偏置 1e7、波动 1 都不出事（0/200 负数）。
   所以在 `stats_node` 里继续用它**没错**，我之前那句警告作废。
2. **真正会炸的是 `float32`。** 偏置一旦升到 1e4~1e6 而波动又小，
   朴素公式会产生**负数方差**——再被 `max(0.0, var)` 兜成 0，
   **标准差恒为 0，而且不报任何错**。最坏的一种 bug：不崩、不叫、就是错。
3. **什么时候会真的遇到 float32？** 两处，而且都在你这条路上：
   - **把这段统计搬到 C / C++（MCU、边缘设备）**——嵌入式里 `float` 是默认选择；
   - **用 numpy 且图省事写成 `dtype=np.float32`**（省内存、或从串口按 4 字节解包）。

### 所以 Welford 还要不要学？

**要，但理由换成「精度无关」，而不是「Python 里会炸」。**

```python
def update(self, v):
    self.n += 1
    d = v - self.mean               # 与当前均值的小偏差（一直是小量）
    self.mean += d / self.n
    self.m2 += d * (v - self.mean)  # 二阶中心矩，直接累加
    # 要标准差：math.sqrt(self.m2 / self.n)
```

它的价值是：**同一份代码，float32 和 float64 都准。**
你的统计逻辑迟早要从 Python 挪到 C（阶段二接 STM32、以后上边缘端），
那时候换公式的代价，比现在多写三行大得多。
**顺带一句**：`阶段三` 的订阅端（`monitor_msg_node`）已经直接用它了。

### 另一个顺手学到的判断

情形 A 那 16% 的「误差」，是 n=50 的统计涨落，不是算错。
所以你之前看到的 `方差=0.497` **恒定不动**，恰恰说明信号是**确定性正弦 + 零噪声**——
一加 `noise`，方差就会开始跳（±20% 量级），**那不是 bug，是统计本身的样子**。
