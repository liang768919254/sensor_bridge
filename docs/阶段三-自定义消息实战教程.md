## 〇、先读这段：这份教程的定位与边界

**一句话目标**

> 不改串口桥的骨架，只换掉它的出口——从一条只有单个数值的 `Float32`，
> 换成能装下「时间 + 坐标 + 多路测量 + 设备时钟」的自定义消息 `SensorData`。

**为什么这一步是阶段一的收尾，而不是新项目**

阶段二结尾我留了一句话：

> 阶段二把协议字段先定下来的回报是：阶段三不再是「重新做一个项目」，
> 而是「给已有的桥换一个出口」。

阶段三要兑现它。你会看到 `serial_bridge_msg_node.py` **只有 60 行**——
因为线程模型、断线自愈、参数、统计、陈旧数据保护**一行都没重写**。
接口定义（.msg）和实现（节点）分开，是本体工程里最值钱的一刀。

**范围红线（依旧是这段最重要）**

时间预算是 **1 个周末 + 1 个晚上**。下面这些看到就跳过：

| 看到就想加的东西 | 为什么现在不加 |
|---|---|
| `srv` / `action` 自定义接口 | 阶段三只做「发布/订阅」；服务与动作留给导航、抓取那类长任务 |
| 给消息加数组（`float32[] samples`） | 会引出「一帧该装几帧数据」的新问题，属于驱动设计，不是接口练习 |
| 二进制协议 / 帧头 / CRC | 只有一端（PC）能自描述不够，两端都改才叫升级 —— 那是 CAN 阶段的事 |
| `ros2_control` / 硬件接口插件 | 完全另一套抽象，等你要做真实关节控制再学 |
| 一次定义七八条消息 | **一条消息 + 一条消息的历史**，比八条没被用过的消息有价值 |
| TF2 广播 `frame_id` | 阶段三只把 `frame_id` **填对并验证变化**；真正发 TF 是下一步 |

## 一、阶段三的明确目标与范围

### 1.1 目标：四个层次

| 层次 | 目标 | 怎么算达标 |
|---|---|---|
| **L1 功能** | 桥发布 `sensor_interfaces/msg/SensorData`；订阅端能拿到结构化字段 | `ros2 topic echo` 里能看到 6 个字段各自的值 |
| **L2 工程** | 接口包与实现包解耦；协议字段与消息字段一一对应且可验证 | 桥的骨架零改动，只多了 60 行子类 |
| **L3 能力** | 能独立判断「什么时候该定义自己的消息」，并把它写出来 | 能口述 v1/v2/v3 协议的取舍，以及为什么用 `Header` 不自己写 stamp |
| **L4 衔接** | 消息里留好 `header.stamp` / `frame_id`，为 TF2 与多传感器做准备 | 能解释「到达时刻 ≠ 采样时刻」，并说清 `mcu_tick_ms` 留来干什么 |

### 1.2 范围：做什么 / 不做什么

**做（In Scope）**

1. 新建接口包 `sensor_interfaces`（ament_cmake），定义 `msg/SensorData.msg`
2. 桥升级为「同一条桥、两个出口」：`serial_bridge`（Float32）+ `serial_bridge_msg`（SensorData）
3. 串口协议升级到 v3：`seq,value,raw_adc,temperature,mcu_tick_ms`
4. 订阅端升级：多通道窗口统计 + 丢帧检测 + 数据年龄 + `frame_id` 变化告警
5. 打包与依赖：`setup.py` / `package.xml` 正确声明跨包依赖
6. 证据：bag 能录能放自定义消息；从零重建一次成功

**不做（Out of Scope，写进"以后再说"）**

srv / action、数组字段、二进制协议、TF2 广播、ros2_control、多消息类型。

### 1.3 结业清单原定 vs 实际采用（这一节是阶段三的核心判断）

结业清单最初写的是：

```python
# 原定
float32 value
float64 stamp      # 自己塞一个浮点秒
string  frame_id
```

**最终采用：**

```python
std_msgs/Header header      # 里面的 stamp 是 builtin_interfaces/Time
uint32  seq
float32 value
float32 temperature
uint16  raw_adc
uint32  mcu_tick_ms
```

| 项 | 原定 | 采用 | 理由 |
|---|---|---|---|
| 时间 | `float64 stamp` | `header.stamp`（`builtin_interfaces/Time`） | `Time` 是 **int32 sec + uint32 nanosec** 的整数对，没有浮点累加误差；而且 **bag 回放、rviz、tf2、image_transport 全认它**。自己塞浮点秒 = 造轮子，接 TF2 时要全部返工 |
| 坐标 | `string frame_id`（裸字段） | `header.frame_id` | `frame_id` 的标准位置就在 Header 里，工具链按这个位置找它 |
| 测量 | `float32 value` | 保留 | — |
| 其它 | — | `+ seq / temperature / raw_adc / mcu_tick_ms` | 阶段二的协议 v2 已经在传这些字段；**不搬进消息，它们就还是"分在几条话题上"的老问题** |

> **这就是判据本身**：什么时候该定义自己的消息？
> **当一组数据在语义上属于同一时刻、必须一起走的时候**（阶段一 D1 的答案）。
>
> 反过来也成立：**能从 ROS 标准消息直接表达的东西，不要自定义。**
> 一个只有 `float32` 的消息，`std_msgs/Float32` 就是它。

### 2.3 认知前置（3 个问题）

**Q1：为什么接口包必须是 `ament_cmake`？**

因为生成消息类靠的是 `rosidl_generate_interfaces()` —— 那是一个 **CMake 宏**。
`ament_python` 包没有 CMake 构建流程，写不出来。
所以标准做法是：**接口单独一个 `ament_cmake` 包，Python 节点用 `import` 去拿**。

**Q2：改了 `.msg`，要重新编译哪些东西？**

三层，缺一不可：
1. 接口包自己（`sensor_interfaces`）——重新生成消息类
2. **所有依赖它的包**（`sensor_bridge`）——Python 侧虽然 `import` 的是软链，
   但 `.msg` 变动会改变消息类结构，`setup.py` 打包时记录的元数据也得刷新
3. 已运行的节点——必须重启（消息类型在进程启动时就绑定了）

**判据回顾（阶段一 A5 的同一条）**：改的是「代码」还是「安装清单/接口定义」？
接口定义属于后者，**必须 build**。

**Q3：为什么 `ros2 topic echo` 能看到字段名，而串口那端还得「猜字段个数」？**

这是个很关键的区分：

| 环节 | 格式是否自描述 |
|---|---|
| 串口（MCU → PC 的一行 ASCII） | ✗ **不自描述**，只能靠字段个数 + 协议文档 |
| 话题（PC 内部 / 下游） | ✓ **自描述**，`ros2 interface show` 一查就知道 |

**自定义消息解决的是"下游"的问题，解决不了"串口这一端"的问题。**
所以协议文档必须和 `.msg` 一起版本化，改一个就得改另一个。
想彻底解决串口侧，得加帧头 + 版本号（那是 CAN 阶段的事）。

### Step 2 · 桥换出口（60 行子类）

**2.1 先看这是怎么做到的**

阶段二的 `serial_bridge_node.py` 里现在多了两个钩子（**行为完全没变**，只是把方法体抽出来）：

```python
class SerialBridgeNode(Node):
    EXTRA_PARAMS: dict = {}          # 子类在这里登记自己额外的参数

    def _create_publisher(self, topic):        # 钩子 1
        return self.create_publisher(Float32, topic, 10)

    def _pack_msg(self, stamp):                # 钩子 2
        msg = Float32()
        msg.data = float(self._latest)
        return msg
```

这叫**模板方法模式**：父类定流程（读 → 解析 → 缓存 → 定时发布），
子类只填两个可变点。换出口 = 覆盖这两个方法，**60 行封顶**。

**2.2 `serial_bridge_msg_node.py` 全文要点**

```python
class SerialBridgeMsgNode(SerialBridgeNode):

    EXTRA_PARAMS = {'frame_id': 'sensor_link', 'temp_scale': 0.01}

    def _create_publisher(self, topic):
        return self.create_publisher(SensorData, topic, 10)

    def _pack_msg(self, stamp):
        return pack_sensor_data(
            SensorData, self._latest_fields, stamp,
            frame_id=self.get_parameter('frame_id').value,
            value_scale=float(self.get_parameter('scale').value),
            temp_scale=float(self.get_parameter('temp_scale').value),
            seq_fallback=self._latest_seq)
```

**注意 `EXTRA_PARAMS` 用类属性**：它在 `super().__init__()` **之前**就能读到，
所以基类的 `__init__` 里可以统一 `declare_parameter`，
子类不用去改基类、也不用在节点建好之后补声明。三行换掉一堆样板。

**2.3 打包与依赖（三处）**

```python
# setup.py —— entry_points 加两行
'serial_bridge     = sensor_bridge.serial_bridge_node:main',       # 阶段二
'serial_bridge_msg = sensor_bridge.serial_bridge_msg_node:main',   # 阶段三

```

```xml
<!-- package.xml —— 用 depend（= build + exec），不要只用 exec_depend -->
<depend>sensor_interfaces</depend>
```

> 只写 `exec_depend` 在某些情况下会被排到接口包前面 →
> 「先编 sensor_bridge、后编 sensor_interfaces」→ import 找不到 → 构建失败。

### Step 3 · 无硬件回环：把一半链路先验完

阶段二用 socat 验了「串口 → 桥」；这一步用**直接发 ROS 消息的假发布者**验「桥 → 话题 → 订阅端」。
两半合起来就是完整链路，而你现在**既不需要板子、也不需要 socat**。

```bash
# 终端 A：假传感器（10Hz 正弦 + 温度通道，可选故意丢帧）
/usr/bin/python3 无硬件自测/fake_sensor_data_pub.py --rate 10 --plus 1650 --drop-every 7

# 终端 B：看结构化内容
ros2 topic echo /sensor/value --once

# 终端 C：频率
ros2 topic hz /sensor/value
```

`--drop-every 7` 会让每 7 帧少发 1 帧（**帧号照跳**），用来验证订阅端的丢帧检测——
这是「话题上有数据」和「数据一帧没丢」的区别，`ros2 topic hz` 是看不出这个的。

> **一个通用的测试技巧**：如果你要测的模块依赖了外部东西（串口、数据库、网络），
> 就**给它一个替身**。我在沙箱里没有 pyserial、也没有 `/dev/pts`，
> 于是写了一个只实现 `Serial / readline / close / SerialException` 的桩模块放进 `PYTHONPATH` 最前面——
> 桥的线程模型、参数、打包、异常处理**被测得一清二楚**，一行代码没改。
> 这不是"绕过测试"，这是标准的依赖隔离。

**产出物**：`fake_sensor_data_pub.py` 能起、`ros2 topic echo` 看到 6 个字段。

### Step 4 · 订阅端升级（多通道统计 / 丢帧 / 数据年龄）

阶段一的 `monitor_node` 只统计一个通道。阶段三有三个新需求，每个都对应真实工程：

| 需求 | 实现 | 为什么 |
|---|---|---|
| **多通道统计** | `ChannelSet(['value','temperature','raw_adc'])` + Welford | 一条消息里有多个物理量，各算各的窗口统计 |
| **丢帧检测** | `SeqTracker` 按帧号算环绕距离 | 「有数据」≠「一帧没丢」 |
| **数据年龄** | `now - header.stamp` | 量的是"发布 → 订阅"在 ROS 图里走了多久 |
| **坐标名变化** | 变了才打一条 info | 日志的价值在"变化"；也是 TF2 的伏笔 |

实测输出长这样：

```
[monitor_msg] 窗口 3.0s | 帧数=30 | 实测 10.00 Hz
  | value: 均值=+1663.500 标准差=699.795 [840.000, 2601.000]
  | temperature: 均值=+24.886 标准差=0.424 [24.400, 25.590]
  | 丢帧=118 乱序=0 重复=0
  | 数据年龄 均=0.001s 峰值=0.002s | frame_id=sensor_link
```

**为什么用 Welford 而不是 `E[v²] − E[v]²`**：不是「Python 里会炸」（实测 float64 下连偏置 1e7 都稳），
而是它**精度无关** ——

| 情形（偏置 ± 波动） | float64 朴素 | float32 朴素 | Welford（float32） |
|---|---|---|---|
| 2048 ± 5 | 1.6e-1 | 1.6e-1 | 1.7e-1 |
| 25000 ± 15 | 1.5e-1 | **11/200 算出负数** | 1.6e-1 |
| 1e6 ± 1 | 1.7e-1 | **88/200 算出负数** | 1.7e-1 |

嵌入式里 `float` 是默认选择，这段统计迟早要搬去 C —— 那时换公式的代价比现在多写三行大得多。

**产出物**：`monitor_msg_node.py`、`sensor_stats.py`（含自检）。

### Step 5 · 接真硬件 + 协议升级到 v3

**5.1 串口协议 v3**

```
<seq>,<value_mv>,<raw_adc>,<temp_c_x100>,<mcu_tick_ms>\n
```

例：`1024,1650,2048,2500,187340`

三个决定：

| 字段 | 类型 | 为什么 |
|---|---|---|
| `seq` | uint32 | 订阅端丢帧检测的依据（不要用 `header.seq`，那个在 ROS2 里已废弃） |
| `value_mv` | 整数毫伏 | **定点整数传输** → MCU 侧完全避开浮点 printf（慢，且要开 MicroLIB / `-u_printf_float`） |
| `temp_c_x100` | 整数 | 同上；PC 侧用 `temp_scale:=0.01` 乘回 ℃ |
| `mcu_tick_ms` | uint32 | **把"到达时刻"和"采样时刻"的差留成可校正的**（见第六节陷阱②） |

**5.2 固件侧只改一行**

```c
/* 原来是 4 字段，现在补上 HAL_GetTick() */
printf("%u,%ld,%lu,%ld,%lu\n",
       (unsigned)seq, (long)mv, (unsigned long)raw,
       (long)temp_c_x100, (unsigned long)HAL_GetTick());
```

**5.3 接板子跑**

```bash
ros2 launch sensor_bridge serial_bridge_msg.launch.py port:=/dev/stm32_bridge
ros2 topic echo /sensor/value --once
ros2 run rqt_plot rqt_plot          # Topic 填 /sensor/value/value（字段级！）
```

**产出物**：v3 协议文档（一页）、固件改动、真机跑通的 `ros2 topic echo` 输出。

```bash
# 跑 30 秒 Ctrl+C
```

实测踩到的坑：

## 六、关键风险点与注意事项

### 6.1 阶段三特有的高频坑

| # | 症状 | 根因 | 处置 |
|---|---|---|---|
| 1 | `ModuleNotFoundError: No module named 'em'`（或 `catkin_pkg` / `numpy`）在接口包编译中途 | CMake 抓到了 PATH 里**别的 python3**（conda / uv / 工具链自带的 3.13），而 `em` 只装在系统 3.10 下 | 让 `python3` 就是 `/usr/bin/python3`；**改完必须 `rm -rf build install` 再 build**。注意 `--cmake-args -DPython3_EXECUTABLE=...` 实测**无效** |
| 2 | `CMake Error ... Packages installing interfaces must include '<member_of_group>rosidl_interface_packages</member_of_group>'` | `package.xml` 漏了那一行（`rosidl_generate_interfaces.cmake:229` 的 FATAL_ERROR） | 补上，重建。**别去折腾 CMake 环境**，问题就在这一行 XML |
| 3 | `Could not find msg 'Header'` | `rosidl_generate_interfaces` 的 `DEPENDENCIES` 里没写 `std_msgs` | 补 `DEPENDENCIES std_msgs` |
| 4 | 改了 `.msg` 加字段，节点报 `AttributeError: 'SensorData' object has no attribute 'xxx'` | 只重建了接口包，没重建依赖它的包 / 没重启节点 | 重建**所有**依赖包 + 重启节点 |
| 5 | `failed to create symbolic link ... Is a directory` | 切换 `--symlink-install` 开关时 `build/` 里留着真目录 | 先 `rm -rf build install` |
| 6 | 先编 sensor_bridge 后编 sensor_interfaces → import 失败 | `package.xml` 里只写了 `exec_depend` | 改成 `<depend>sensor_interfaces</depend>` |
| 7 | 两个包各定义一条同名消息 | ROS2 里消息类型名**全局唯一** | `ros2 interface list \| grep` 先查重；本教程用 `sensor_interfaces` |
| 8 | 桥启动了但 `Publisher count: 0` | 节点的 `import serial` 失败（没装 pyserial），进程直接退出 | `ros2 run` 的输出会带完整 traceback，**先看它，别猜** |
| 9 | `ros2 topic hz` 正常但 `rqt_plot` 画不出线 | Topic 框没填到字段级 | 填 `/sensor/value/value`（阶段一 A7 考过） |

### 6.2 只有真跑才会暴露的两个发现

**发现 ①：「最新值 + 定时器」策略一定丢中间帧 —— 这是设计后果，不是 bug**

实测：桩串口按 50 Hz 喂数据，桥按 10 Hz 发布，订阅端（10 Hz）报 `丢帧=118`。
不是谁坏了，而是**这条桥有意只保留"最新值"**：源比发布快 5 倍，中间 4 帧必然被覆盖。

**这直接决定了下游该怎么选**：

| 下游要什么 | 该用哪种策略 |
|---|---|
| 实时最新状态（可视化、闭环控制、遥测） | **最新值 + 定时器**（本教程的做法）：等间隔、不堆积、天然抗突发 |
| 完整序列（数据回放、算法训练集、故障复现） | 「收到就发」或加队列全发 —— **否则你会得到一份"看起来连续但少了 80% 数据"的 bag** |

**判据：你这一帧数据，下游是要"现在是多少"还是"全都给我"？**
答不出来就先别写。

**发现 ②：数据源停发后，最后一帧会被重复发布**

实测：桩串口停发后，订阅端报 `重复=1`。
原因：桥在 `stale_timeout`（默认 1 s）之内还在按定时器发那个"最后已知值"。

这是**有意的**——下游不该因为一次抖动就突然断流。
但如果你在**记录序列**，就必须用 `seq` 去重，否则这份数据里会混进重影。
（这正是 `SeqTracker` 里 `重复` 那一路的用处。）

### 6.3 三个「看起来对但不对」的陷阱

**陷阱 ①：以为 `ros2 topic echo` 能替代「串口侧的协议校验」**

`echo` 显示得再漂亮，也只证明**消息构造对了**。
如果 MCU 把字段顺序发错（比如 `temp` 和 `raw_adc` 换了位置），
你会在 echo 里看到两个"数值合理但含义错位"的字段，**一眼看不出来**。
对策：**用物理量本身做校验**——`raw_adc` 必须 ∈ [0,4095]、
`temperature` 必须和室温对得上、`value_mv` 必须随你拧电位器单调变化。
**数值的"合理"比"存在"重要。**

**陷阱 ②：拿 `header.stamp` 当"采样时刻"**

它标的是**发布时刻**（也就是 PC 收到的时间），包含了串口传输 + 缓冲 + 调度延迟。
正确的做法有两条，选一条并**写下来**：
- 接受「到达时刻 = 采样时刻」，并在文档里**明确写下这个假设**；
- 或者用 `mcu_tick_ms` 做一次线性拟合，把两条时间轴对上。
**写下来就不算错，不写下来就是埋雷。**

**陷阱 ③：为了"消息更好看"频繁改 `.msg`**

每改一次，接口包 + 所有依赖包都要重建，已跑的节点要重启。
**`.msg` 是契约**，改它等于改 API。
建议：**动手前先把字段表写在一页纸上**（字段名 / 类型 / 单位 / 谁来填），
确定之后再写 `.msg`。本教程的 `SensorData` 就是先有协议 v3 的字段表，
`.msg` 只是它的"ROS 版翻译"。
