### 2.3 关键代码模式（这三段值得背）

**① 节点骨架五件套** —— 每个节点的 `main` 都长这样

```python
def main(args=None):
    rclpy.init(args=args)                 # 1 初始化
    node = MyNode('node_name')            # 2 建对象（里面 __init__ 干完所有 create_）
    try:
        rclpy.spin(node)                  # 3 派发事件（阻塞，直到 Ctrl+C）
    except (KeyboardInterrupt, ExternalShutdownException):
        pass
    finally:
        node.destroy_node()               # 4 清理
        if rclpy.ok():
            rclpy.shutdown()              # 5 关周
```

**② 回调签名是硬性规定，写错必炸**

| 回调 | 签名 | 写错的后果 |
|---|---|---|
| 订阅回调 | `def cb(self, msg):` | 少参数 → `TypeError` |
| 定时器回调 | `def cb(self):` | 多写 `msg` → `TypeError: missing 1 required positional argument` |
| `__main__` 守卫 | `if __name__ == '__main__':` | 写成 `'__name__'` → **程序起来什么都不做，且不报错**（最难查的一类） |

**③ 参数要分两类 —— 这是「参数化」真正的全部内容**

| 类型 | 谁 | 怎么读 | 例子 |
|---|---|---|---|
| **结构参数** | 决定对象怎么建 | 启动时读一次，改了要重启 | `rate`（定时器周期）、`port`、`baud` |
| **数据参数** | 只影响每帧算出的数 | **每帧现读**，`ros2 param set` 立刻生效 | `amplitude`、`freq`、`noise`、`wave`、`scale` |

### 2.4 这一阶段真正掌握的知识

**A. 执行器与回调并发（A8 那道题的价值）**

默认 `SingleThreadedExecutor` 下，一个节点里所有定时器/订阅回调**共用一个线程排队**。
某一个回调跑 0.5 秒，其余全部排队等着 → 延迟甚至丢帧。
想避免只有两条路：**拆成独立节点**（最常用）或 **换 `MultiThreadedExecutor` + `MutuallyExclusiveCallbackGroup`**。

**B. 边收边算 vs 攒着算（A4）**

```python
self.values.append(v)          # O(n) 内存：100 万帧 ≈ 8MB，跑一整天就飞了
self.count += 1; self.total += v   # O(1)：三个变量，跑一年也一样
```

**C. 窗口统计要清零，而且要写成赋值**

```python
self.count == 0      # ❌ 是「比较」，语句没有副作用 —— 累加器永不清零，窗口退化成累计统计
self.count = 0       # ✅
```
已验证修好了：09-19 实测 stats_node 输出方差恒 0.497、均值 ±0.058 交替，11 行纹丝不动 → 清零生效。

**D. 给自己留一个「理论锚点」（★ 最值钱的一招）**

```
正弦波的方差闭式解：  Var = A²/2        Std = A/√2
一行恒等式自检：      var + mean² ≡ A²/2        （纯正弦、无噪声时）
```
实测 `0.497 + 0.058² = 0.50036 ≈ 0.5` ✅。
**没有理论值的输出，你只能看出「它在动」，看不出「它对不对」。**
顺带解释了另一件事：n=50 时方差估计本身就有 `√(2/(n-1)) ≈ 20%` 的统计涨落 —— **加了 noise 之后方差开始跳，不是 bug。**

**E. `ros2 param` 与 validator (验证器)的三个坑**
- `gauss(0.0, 0.0)` 恒返回 `0.0` —— σ=0 时正态分布退化成尖峰，**不是随机数没生效**
- `declare_parameter('amplitude', 'Float32')` → 默认值是字符串，后面乘法直接 `TypeError`
- rqt_plot 的 Topic 必须填到字段级：`/my_sensor/v/data`，嵌套就逐层 `/linear/x`

### 3.3 关键代码：整座桥的心脏

```python
# 读线程里（另开线程，绝不放在 spin 线程）
line = self._ser.readline()               # timeout=0.2 必须有，否则永久阻塞
fields = parse_line(line, self.raw_line_max)
self._latest = fields[0]                  # 只更新「最新值」
self.rx_frames += 1

# 发布定时器里（固定 10Hz）
if now - self._last_rx > self.stale_timeout:
    self._maybe_warn_stale()              # 陈旧数据：不发！只告警一次
    return
self.pub.publish(self._pack_msg(now))     # 等间隔发布
```

| 异常 | 策略 |
|---|---|
| 设备不存在 / 打开失败 | 不崩，进「未连接」态，每 1 秒重试，日志 `throttle_duration_sec=5.0` |
| 断线（拔 USB） | `SerialException` → 关句柄 → 转未连接 → 继续重试 |
| 解析失败（上电横幅 / 乱码） | **静默** `bad_frames += 1`，汇报时一起报（绝不逐条打日志） |
| 超长行 / 半包 | > `raw_line_max`（256 字节）直接丢 |
| 陈旧数据 | 超时就不发布 —— **下游绝不能拿到「你以为实时、其实是五分钟前」的值** |

**参数表**（最终形态）：`port` / `baud` / `topic` / `publish_rate` / `report_period` / `raw_line_max` / `stale_timeout` / `scale` —— 全部实测注册成功。

### 3.4 这一阶段真正掌握的知识

**A. 读串口必须开独立线程 —— 理由要能说出三件坏事**
`serial.readline()` 是阻塞调用。放在 `spin` 线程里 → 定时器不响、参数服务不应答、`ros2 node info` 卡死、Ctrl+C 关不掉、`/rosout` 不更新。
`MultiThreadedExecutor` 救不了它 —— **串口 IO 不是 ROS 回调，执行器管不着**。

**B. 时间语义：为什么 Tue.*scan 用「定时器 + 最新值」而不是「收到就发」**
1. **频率解耦**：源想发多快都行，下游看到的是等间隔数据
2. **陈旧数据保护**：板子挂了，手上那个值会变成几分钟前的鬼魂

> 代价（阶段三才量出来）：**这条桥一定会丢中间帧**。桩按 50Hz 喂、桥按 10Hz 发 → 订阅端报 `丢帧=118`。
> 这不是 bug，是设计后果。判据：**你的下游是要「现在是多少」还是要「全都给我」？**

**C. 设备名不能写死，udev 靠 VID:PID（+序列号）匹配**
`/dev/ttyUSB0` 是内核按**枚举顺序**给的临时名字。

```bash
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", \
  SYMLINK+="stm32_bridge", GROUP="dialout", MODE="0660"
```

**D. 「从频率反推数据来源」是一次教科书级诊断（09-20 实录）**

| 现象 | 数字 | 它在说什么 |
|---|---|---|
| 终端满屏 `data: .inf` | — | 正常帧**全被丢了**，不是没收到数据 |
| `ros2 topic hz` = **0.198 Hz** | ≈ 1/5.05 | 正好是坏数据块每 5 秒来一次的频率 |
| 为什么偏偏 `inf` 活下来 | — | 那条 600 字节超长行内容全是数字，`float('9'*600)` 不报错、返回 `inf` |

根因：sender 默认发 v2 四字段 `214,2768,3434,2468`，而最小版桥用 `float(text)` 只认单值。加 `--v1` 后 `hz` 立刻回到 **20.17~20.24 Hz**。

**E. 先软后硬：`socat` 虚拟串口让 70% 工作量不等硬件**

```bash
socat -d -d pty,raw,echo=0,link=/tmp/ttyV0 pty,raw,echo=0,link=/tmp/ttyV1
```

**F. STM32 侧的四条**（09-21 实跑通过，09-22 复核补第 2 条）
- `printf` 浮点要开 MicroLIB / `-u_printf_float`，否则**静默失效**
- **★ `setvbuf(stdout, NULL, _IONBF, 0)` 不能漏**：nano.specs 下 stdout 是**全缓冲**（≈1024B），每帧 6 字节要攒 170 帧 → **约 17 秒才吐一次**。漏了它你会去查波特率、接线、ADC，越查越远
- 行尾必须带 `\n`（`readline` 靠它切帧）；不要在中断里 `printf`；`_write` 只能有一份（`syscalls.c` 里已有了）
- **F103C8T6 的 `st-info` 报 128K 不是误报**（读 `F_SIZE` 寄存器），但链接脚本按 64K 保守是对的，**绝不能改 128K**

> 工程：`~/stm32_ws/adc_serial_nocube/`（免 CubeMX，注意名字带 `_nocube`）。
> 09-22 实测 `make size` → `text=15352 / data=120 / bss=1712`，离 64K 红线很远。

**G. 补到文档里的 Linux 能力**：pyserial 装给 `/usr/bin/python3`、dialout 要**注销重登**、Ubuntu 的 **brltty 会抢 CH340**、`dmesg` 里看 `ch341-uart disconnected`

## 4. 阶段三：自定义消息（教程 + 参考源码齐了，代码未落 `ros_study`）

### 4.1 要求

目标：**不改桥的骨架，只换出口** —— 从单个 float 换成 `SensorData`（时间 + 坐标 + 多路测量 + 设备时钟）。
范围红线：不做 srv/action、不加数组字段、不做 TF2 广播、不定义七八条消息。

**最核心的一次判断**：结业清单原定的 `float64 stamp + string frame_id` 被改掉了。

| 项 | 原定 | 采用 | 理由 |
|---|---|---|---|
| 时间 | `float64 stamp` | `header.stamp`（`builtin_interfaces/Time`） | `Time` 是 int32 sec + uint32 nanosec **整数对**，无浮点累加误差；**bag / rviz / tf2 / image_transport 全认它** |
| 坐标 | `string frame_id`（裸字段） | `header.frame_id` | 工具链按标准位置找它 |
| 其它 | — | `+ seq / temperature / raw_adc / mcu_tick_ms` | 阶段二 v2 协议已经在传这些；不搬进消息，它们就还是「分在几条话题上」的老问题 |

### 4.2 实现（参考源码全在 `09_阶段三_自定义消息实战/参考源码/`）

**SensorData.msg**

```
std_msgs/Header header      # stamp = 到达时刻；frame_id = 安装坐标名
uint32  seq                 # MCU 帧号，订阅端用它检测丢帧
float32 value               # 主工程量（默认 mV）
float32 temperature         # ℃
uint16  raw_adc             # 0~4095
uint32  mcu_tick_ms         # MCU 上电以来的 ms
```

**桥换出口只用了 60 行 —— 模板方法模式**

```python
class SerialBridgeMsgNode(SerialBridgeNode):     # 继承，骨架一行没写
    EXTRA_PARAMS = {'frame_id': 'sensor_link', 'temp_scale': 0.01}   # 类属性：在 super().__init__() 之前就能读到

    def _create_publisher(self, topic):          # 钩子 1
        return self.create_publisher(SensorData, topic, 10)

    def _pack_msg(self, stamp):                  # 钩子 2
        return pack_sensor_data(SensorData, self._latest_fields, stamp, ...)
```

**协议 v3（行协议）**：`<seq>,<value_mv>,<raw_adc>,<temp_c_x100>,<mcu_tick_ms>\n`
关键取舍：**全整数定点传输** → MCU 侧完全避开浮点 `printf`（慢，还要开 MicroLIB）；PC 侧用 `scale` / `temp_scale` 乘回来。

**订阅端升级**：多通道 Welford 统计 + `SeqTracker`（丢帧/乱序/重复）+ 数据年龄 + frame_id 变化告警。
实测输出：

```
[monitor_msg] 窗口 3.0s | 帧数=30 | 实测 10.00 Hz
  | value: 均值=+1663.500 标准差=699.795 [840.000, 2601.000]
  | 丢帧=118 乱序=0 重复=0 | 数据年龄 均=0.001s 峰值=0.002s
```

### 4.3 这一阶段真正掌握的知识

**A. 什么时候该自定义消息（判据成型）**
> **当一组数据在语义上属于同一时刻、必须一起走的时候。**
> 反过来：**能从 ROS 标准消息直接表达的东西不要自定义** —— 一个只有 float32 的消息，`std_msgs/Float32` 就是它。

两条话题（`value` 和 `noise`）的问题是**帧不对齐**：两次独立 publish，DDS 不保证到达顺序。10Hz 看不出来，做数据记录 / 闭环控制 / 离线回放时就会出错。

**B. 接口包必须 `ament_cmake`，`member_of_group` 漏了是构建期 FATAL_ERROR**
生成消息类靠 `rosidl_generate_interfaces()` —— 那是个 **CMake 宏**，ament_python 包没地方放。
> 实测更正：不是「能编译但 `ros2 interface list` 看不见」，而是直接失败：
> `Packages installing interfaces must include '<member_of_group>rosidl_interface_packages</member_of_group>'`
> 出自 `rosidl_generate_interfaces.cmake:229`。**看到这句就直奔 `package.xml`，别去折腾 CMake 环境。**

**C. 跨包依赖要写 `<depend>` 而不是 `<exec_depend>`**
colcon 靠 package.xml 决定**编译顺序**；只写 exec_depend 有可能先编 `sensor_bridge` → import 失败。

**D. 串口和话题，一个是「不自描述」一个是「自描述」**

| 环节 | 自描述？ |
|---|---|
| 串口一行 ASCII | ✗ 只能靠字段个数 + 协议文档 |
| ROS 话题 | ✓ `ros2 interface show` 一查便知 |

**所以协议文档必须和 `.msg` 一起版本化。** `.msg` 是契约，改它等于改 API（接口包 + 所有依赖包重建 + 重启节点）。

**E. 用 Welford 而不是 `E[v²] − E[v]²` 的理由（实测推翻了最初的说法）**

| 情形（偏置 ± 波动） | float64 朴素 | float32 朴素 | Welford |
|---|---|---|---|
| 2048 ± 5（真 ADC 长相） | 1.6e-1 | 1.6e-1 | 1.6e-1 |
| 25000 ± 15 | 1.5e-1 | **11/200 算出负数** | 1.6e-1 |
| 1e6 ± 1 | 1.7e-1 | **88/200 算出负数** | 1.7e-1 |

修正后的结论：**Python float64 下朴素公式是安全的**（偏置 1e7 都不出事，0/200 负数）；
真正会炸的是 **float32** —— 负数方差被 `max(0.0, var)` 兜成 0，**标准差恒为 0 且不报任何错**。
所以换 Welford 的正当理由是「精度无关」：这段统计迟早要搬到 C / MCU，那时换公式代价大得多。

```python
def update(self, v):
    self.n += 1
    d = v - self.mean
    self.mean += d / self.n
    self.m2 += d * (v - self.mean)      # σ² = m2 / n
```

**F. `header.stamp` 标的是到达时刻，不是采样时刻**
包含串口传输 + 缓冲 + 调度延迟。两条出路选一条**并写下来**：接受「到达 ≈ 采样」并在文档里明说；或用 `mcu_tick_ms` 做线性拟合对时轴。**写下来就不算错，不写下来就是埋雷。**

**G. 依赖隔离：给外部依赖一个替身**
沙箱里没有 pyserial、也没有 `/dev/pts` → 写一个只实现 `Serial / readline / close / SerialException` 的桩模块放进 `PYTHONPATH` 最前面，一行被测代码都不用改。
> ⚠️ 但记住：**桩类只能证明逻辑对，证明不了类型对。** 传字符串当 `stamp`，桩类下 21/21 全绿，换真类立刻炸 `The 'stamp' field must be a sub message of type 'Time'`。

## 5. 三阶段横向透视

### 5.1 协议演进一条线

| 版本 | 格式 | 阶段 | 解决了什么 | 还差什么 |
|---|---|---|---|---|
| v1 | `1.234\n` | 二 Step2 | 最小闭环 | 只有一个值 |
| v2 | `seq,value,raw,temp\n`（4 字段） | 二 Step7 | 多字段同桌 | 还得分流到多条话题 |
| v3 | `seq,value_mv,raw_adc,temp_c_x100,mcu_tick_ms\n` | 三 Step5 | 全整数定点 + 设备时钟 + 丢帧检测 | 串口侧仍不自描述（CAN 阶段解决） |

### 5.2 「要不要重新 build」这条判据用了三次

| 改了什么 | 要 build 吗 |
|---|---|
| Python 源文件（解析逻辑、超时值）—— `--symlink-install` 下 | 不用 |
| `setup.py` 的 `entry_points` | **要**（是安装元数据，写进 egg-info；旧入口名还会残留在 `install/`） |
| `.msg` 接口定义 | **要**，且接口包 + **所有依赖它的包**都要重建，节点还要重启 |

### 5.3 三刀落下之后，能力升级在哪

| 刀 | 切在哪 | 效果 |
|---|---|---|
| 第一刀：**设计** | 先用假数据把接口定死 | 硬件没到，链路先通 |
| 第二刀：**工程** | 阻塞 IO 挪出去 + 异常分级处理 | demo → 能长期跑的东西 |
| 第三刀：**分层** | 接口定义(`.msg`) 与实现(节点) 分离 | 换传感器不改下游、换下游不改传感器 |
